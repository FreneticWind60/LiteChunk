概览

ChunkBridge SDK 是 LiteChunk 转换引擎的独立封装。它把 Chunker 的 Java 版 / 基岩版互转、版本目录、 存档检测与压缩包处理全部打进一个 Android 库，宿主应用只需要一次 Gradle 依赖，不必安装 LiteChunk， 也不必随包分发 Minecraft。

引擎以 dex 资源的形式随 AAR 分发，运行时加载进独立的 :chunkbridge 前台服务进程。 检测、转换、取消都通过公开 API 完成，回调固定回到主线程，错误以 ErrorCode 返回而不是 展示字符串。

一个 AAR 带走引擎

约 1.7 MB，引擎 dex、LevelDB、LZ4、方块映射与语言文件全部内置，不额外下载运行时。

  • 自包含
  • 无外部依赖

不装 LiteChunk

宿主应用与 LiteChunk 完全解耦；转换全程在本机完成，不发起任何网络请求。

  • 离线
  • 无账号

稳定的契约

api 产物承载 ChunkerEngine 契约，先由宿主类加载器加载，之后才挂载引擎 dex。

  • 独立 api
  • R8 友好

进度与取消

onProgress 回传阶段与比例，ConversionHandle.cancel() 随时终止。

  • 主线程回调
  • 可取消

SDK 从 LiteChunk 应用中拆分而来，引擎版本 1.21.0，当前版本为 1.0.2（新增盔甲架姿势双向转换，三个版本号可写）。 它与 LiteChunk 同源、同步升级；详情见仓库的 版本说明。

能做什么

公开 API 刻意保持窄：做转换与检测，外加 level.dat 的读取与修改（1.0.1 起；1.0.2 起三个版本号也可写）；不提供界面，也不接管文件管理与解压。

能力入口说明
初始化 ChunkBridge.initialize(context) 每个进程调用一次，准备引擎 dex 与资源；真正的引擎在服务进程首次使用时才加载。
列出支持版本 ChunkBridge.formats()
ChunkBridge.formatGroup(id)		 读取内置目录，同步返回，开销极小，可在主线程调用。
检测存档 ChunkBridge.detect(File, DetectionCallback)
ChunkBridge.detect(Uri, DetectionCallback)		 支持世界文件夹、.zip、.mcworld、.rar、.7z、 .tar 与 .gz；异步执行。
转换 ChunkBridge.convert(ConversionRequest, ConversionCallback) 返回 ConversionHandle；支持世界文件夹、.zip 与 .mcworld 输入。
读取 / 修改 level.dat ChunkBridge.inspectLevel(File, LevelCallback)
ChunkBridge.applyLevel(File, Map, LevelCallback)		 接受已解开、含 level.dat 的世界目录；返回字段清单（名称、种子、游戏模式等）与提示。 只写 level.dat，不碰区块；压缩包的解开与写回由调用方负责。
取消 ConversionHandle.cancel() 结束 :chunkbridge 进程，这是中断引擎的唯一方式。

引擎支持到所捆绑 Chunker 源码已知的最新版本，撰写时为 Java 26.3.0 / 基岩 1.26.60。 权威列表请以 ChunkBridge.formats() 的返回值为准。

快速开始

环境要求

minSdk27（Android 8.1）
compileSdk35 或更高
Java17（库以 Java 17 字节码编译）
宿主构建AGP 8.x 或更高

安装

SDK 从 GitHub Release 分发，还没有发布到 Maven Central。下载 chunkbridge-sdk-1.0.2-maven-repo.zip 解到你自己的目录（比如 libs/）， 然后在宿主工程里指向它：

settings.gradle.ktsKotlin DSL
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        maven { url = uri("libs") }   // 解压出来的本地仓库
    }
}

也可以在自己的机器上从源码发布到本地 Maven：

终端bash
./gradlew :api:publishToMavenLocal :library:publishReleasePublicationToMavenLocal

然后加入依赖：

app/build.gradle.ktsKotlin DSL
dependencies {
    implementation("com.frenetic.chunkbridge:chunkbridge:1.0.2")
    // api 会通过传递依赖引入；这里只是显式列出
    // implementation("com.frenetic.chunkbridge:api:1.0.2")
}

如果只拷贝单个 AAR 文件，必须同时加入 api-1.0.2.jar：引擎 dex 挂载前， ChunkerEngine 必须已经存在于宿主的类加载器中，否则会得到 ENGINE_UNAVAILABLE。

或者：git submodule + 复合构建

想跟着 SDK 源码一起改（比如调引擎参数、改错误文案），把仓库挂成 submodule，让 Gradle 直接编译源码， 不用每次重新发布 AAR：

终端bash
git submodule add https://github.com/FreneticWind60/ChunkBridge.git chunkbridge
git submodule update --init --recursive
settings.gradle.ktsKotlin DSL
val sdkDir = providers.gradleProperty("chunkbridge.sdk.dir").getOrElse("chunkbridge")

includeBuild(file(sdkDir)) {
    dependencySubstitution {
        substitute(module("com.frenetic.chunkbridge:chunkbridge")).using(project(":library"))
        substitute(module("com.frenetic.chunkbridge:api")).using(project(":api"))
    }
}

本地开发时可以用 -Pchunkbridge.sdk.dir=../sdk 指向旁边的 SDK 检出。复合构建需要 SDK 源码， CI 上记得带上 submodule（--recursive）；同一工程里不要同时用 AAR 和 includeBuild。

初始化

Application.javaJava
@Override
public void onCreate() {
    super.onCreate();
    ChunkBridge.initialize(getApplicationContext());
}

用法

列出目标版本

Formats.javaJava
for (FormatGroup group : ChunkBridge.formats()) {          // "JAVA"、"BEDROCK"
    for (FormatVersion version : group.getVersions()) {    // 新版本在前
        Log.i("ChunkBridge", version.getDisplayName() + " -> " + version.getFormatId());
    }
}

检测存档

Detect.javaJava
ChunkBridge.detect(inputUri, (result, error) -> {
    if (result != null) {
        Log.i("ChunkBridge", result.getEditionLabel() + " " + result.getVersion());
    } else {
        Log.w("ChunkBridge", "detect failed: " + error.getCode());
    }
});

开始转换

Convert.javaJava
ConversionHandle handle = ChunkBridge.convert(
        new ConversionRequest.Builder()
                .inputUri(inputUri)              // 世界文件夹、.zip 或 .mcworld
                .outputUri(outputUri)            // SAF 创建，或使用 outputFile(File)
                .targetFormatId("BEDROCK_1.26.60")
                .convertEntities(true)           // 默认 true
                .build(),
        new ConversionCallback() {
            @Override public void onProgress(double fraction, Stage stage) {
                // fraction: 0.0 .. 1.0，单调递增但并非线性
            }

            @Override public void onCompleted(ConversionResult result) {
                // result.getOutputBytes() / getTargetVersion() / getElapsedMs()
            }

            @Override public void onFailed(ChunkBridgeException error) {
                // error.getCode(): INPUT_UNREADABLE、BUSY 等
            }

            @Override public void onCancelled() {
                // 取消是尽力而为，可能留下 .part 输出
            }
        });

// 之后可在任意线程取消
handle.cancel();

输入与输出必须各指定一个：inputFile(File) / inputUri(Uri)， 以及 outputFile(File) / outputUri(Uri)。其他可选项包括 leanMode(boolean)（低内存设备使用更小的缓冲区）、overwriteExisting(boolean) （仅对 outputFile 生效）、deleteSourceArchiveAfterSuccess(boolean) （仅对压缩包输入生效）与通知标题 / 文案。

Stage 与取消

Stage 表示引擎当前所处的阶段：TERRAIN、ENTITIES、 COMPACT、FINISH、UNKNOWN。取消会结束 :chunkbridge 进程；若请求到达时服务仍存活，回调会收到 onCancelled。 紧接着发出的请求可能仍返回 BUSY，重试一次即可。

读取与修改 level.dat

Level.javaJava
// 传入已解开、含 level.dat 的世界目录
ChunkBridge.inspectLevel(worldDir, (info, error) -> {
    if (info == null) return;                 // error.getCode(), error.getMessage()
    for (LevelField field : info.getFields()) {
        Log.i("ChunkBridge", field.id + " = " + field.value);
    }
});

// 只传要改的字段；未知 id 会被忽略
Map<String, String> changes = new HashMap<>();
changes.put("LevelName", "新的世界");
ChunkBridge.applyLevel(worldDir, changes, (info, error) -> { /* 写入后重新读取的最新值 */ });

读写 level.dat 不需要前台服务，也不碰 Minecraft 的区块数据；压缩包里的 level.dat 解出与写回由调用方负责。字段类型见 LevelField.KIND_*， KIND_ENUM 的可选值在 optionIds 里。

错误码

ChunkBridgeException.getCode() 返回类型化的 ErrorCode，可直接用于分支处理。

错误码含义
INPUT_UNREADABLE输入不存在、不可读，或 URI 授权已失效。
ARCHIVE_UNSUPPORTED不支持的压缩格式。
ARCHIVE_DAMAGED压缩包损坏，或使用了不支持的压缩特性。
WORLD_NOT_FOUND输入在三层目录内都找不到 level.dat 或基岩版 db/。
FORMAT_UNSUPPORTEDtargetFormatId 不在 ChunkBridge.formats() 中。
OUTPUT_UNWRITABLE输出 URI / 文件无法创建，或路径不是绝对路径。
OUTPUT_EXISTSoutputFile 已存在且 overwriteExisting(false)。
INSUFFICIENT_STORAGE写入时设备空间不足。
OUT_OF_MEMORY转换进程堆内存耗尽。
BUSY已有转换在进行，或在转换期间请求了检测；结束后重试。
CANCELLED请求被取消。
ENGINE_UNAVAILABLE引擎 dex 无法加载（通常是 AAR 损坏或被裁剪）。
FOREGROUND_NOT_ALLOWEDAndroid 拒绝启动前台服务，见下一节。
INTERNAL其他错误；getDetail() 携带引擎信息。

前台服务规则

转换运行在 :chunkbridge 进程的 dataSync 前台服务中。下面几条不是建议， 而是平台要求：

  • Android 12+ 调用 ChunkBridge.convert(...) 时宿主必须处于前台，例如 Activity 回调里；否则会立即以 FOREGROUND_NOT_ALLOWED 失败。
  • Android 13+ 需要 POST_NOTIFICATIONS 权限，进度通知才可见；部分厂商 ROM 会把「通知不可见的前台服务」判为保活滥用并杀掉进程，即使不在意通知也建议申请。
  • Android 15+ 对 dataSync 前台服务限制每天 6 小时；单次转换通常远低于该配额，超大批量需要自己的可见流程与调度。

转换期间请保持界面可见。在后台开始的长转换，可能被激进省电的 ROM 直接终止；这是平台与厂商策略， SDK 无法绕过。

限制

  • 每个进程同一时间只做一次转换，并发请求返回 BUSY。
  • SDK 不设置 android:largeHeap；预期处理大世界时建议宿主自行开启，引擎缓冲区会自适应，但更大的堆能减少重试。
  • 解压设有上限：50 万条目、单条目 8 GiB、总计 32 GiB，用于阻挡解压炸弹。
  • 压缩包大于 cacheDir 可用空间时无法落盘暂存；写入前会检查剩余空间。
  • 取消是杀进程，可能留下 .part 输出；作业目录会在服务下次启动时清理。
  • 除 Stage 外没有更细的世界级进度，也没有剩余时间预估。
  • 不编辑 level.dat、不提供文件浏览器、不处理导入 Intent、不提供分享面板——这些仍是你自己的界面。
