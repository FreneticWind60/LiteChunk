安装

从 发布页 下载 APK 直接安装，最低支持 Android 8.1（API 27）。

应用不需要任何存储权限，所有文件都写在 /Android/data/com.frenetic.litechunk/ 下。

  • 系统可能提示「未知来源应用」，在设置里允许一次即可。
  • 后续版本使用同一套签名，可以直接覆盖升级，队列与输出目录都保留。

导入存档

转换页点「添加存档」，可以直接选文件，也可以从别的应用把存档分享进来。

  • .zip 与 .mcworld 直接选，不用先解压。
  • 已解压的世界文件夹同样可以选。
  • 微信、QQ、网盘里点「用其他应用打开」也能进来，应用会先把文件复制一份再入队。

压缩包格式支持 RAR 4/5、7z、tar、tar.gz。对于分卷压缩包、带密码的压缩包，以及 bz2 / xz / lzh 等格式不支持，需要先在 MT 管理器 等软件上解开。

转换

选目标

每个存档都要选目标格式（Java 版 / 基岩版）与目标版本。版本列表由引擎给出，从旧版一路覆盖到最新版。

输出命名

默认按「原名 - 版本标记 - 时间戳」拼，例如 我的世界-BE-20261001-0043.mcworld。 三块都能单独开关，按住右侧手柄可以拖动排序，分隔符可选 -、_ 或不加。 重名不会覆盖，会自动加 (2) 等序号。

几个开关

  • 打包为 .mcworld：只对基岩版目标有效，取消后输出 .zip（两者内容一致）。
  • 转出后自动删除原存档：默认关闭。勾上后也只在打包成功之后才删，转换失败不会丢原档。

转换中

进度卡会显示当前阶段、百分比与已用时，长任务期间可以随时取消。

转换期间请让应用停在前台，最好别灭屏。厂商的省电策略会在灭屏后挂起 CPU，表现出来就是「切后台进度不动，回来才继续甚至转化失败」。应用已经申请了唤醒锁并引导添加白名单，但仍以亮屏最稳。

取出成品

所有产出都在 Android/data/com.frenetic.litechunk/output/，文件页里可以直接管理。

  • 左滑整行展开操作：装填、详情、导出、分享、导入、删除。
  • 右滑整行进入多选，批量删除、导出或分享。
  • 「导出」只是另存一份副本，output/ 里的原件不动。
  • 「导入」会把存档直接放进已安装的基岩版游戏目录，没装游戏就没有这一项。

Android 11 起系统文件管理器进 Android/data 很费劲，建议一律用应用里的「导出」另存到你自己的文件夹。

存档详情

很多「转换没解决问题」的疑难其实不是转换：存档只是改个名字、换个游戏模式，或者声明错了版本。 这种情况走完整转换会把每个区块重新编码一遍，大存档要好几分钟；只改 level.dat 是毫秒级，而且不动区块。

能改什么

只做基础项目，改完逐字段读回校验再替换原文件。

  • Java 版：存档名、游戏模式、难度、作弊开关、种子、出生点、时间。
  • 基岩版：存档名、游戏模式、难度、命令开关、世界类型、种子、出生点、时间。
  • DataVersion / StorageVersion / NetworkVersion 一律只读 —— 改这些数字只改声明、不升级区块，反而容易让游戏判定存档损坏。

保存与另存为

点「保存」会二次确认并写明「覆盖后不可找回」； 想留原档就用「另存为」，它会用新时间戳产出一个新包，原文件不动。

常见问题

存档会被上传到服务器吗？

不会。转换完全在本机完成，引擎随安装包一起分发。整个应用只有「检查更新」一处网络请求，取不到就明说取不到。

转换要多久？

取决于存档大小与设备。几十 MB 的存档通常在几十秒内，几 GB 的大存档会到十几分钟。

事实上，对比 同类软件，LiteChunk 的转换速度确实稍有逊色。这往往并非源于您的设备性能不足，转换期间内存占用很难接近设备上限（不是我不想要内存啊实在是受限于 ART 沟槽的性能调度）。所以请您耐心等待，或者通过小窗/分屏方式给软件保活，这样您就可以在漫长的转换过程中挑战一些有趣的数学难题，不再关注这件事情了（？）。

为什么切到后台进度就停了？

切到后台，电池优化策略可能阻止软件正常运行。您可以通过分屏/小窗的方式，保证您时时刻刻能够看到转换进度，这样，您就可以边转换边干其他事情了。

输出文件在哪？为什么在文件管理器里找不到？

在 Android/data/com.frenetic.litechunk/output/。Android 11 之后系统限制了对这个目录的访问，用应用内的「导出」另存一份最省事。

能转换网易版的存档吗？

不能。LiteChunk 只处理标准 Java 版与基岩版存档，网易版用了自己的加密与结构，不在支持范围内。

要想转换网易版，这边还是推荐您选择 Chunkoid 喵

转换后有些生物没跟过去？

实体转换从 Build4 开始支持，仍在补齐。会跟着走的有：装备与坐骑装备、外观变体（羊毛色、马毛色与斑纹、猫狗品种、热带鱼花纹等）、项圈与坐下、村民的职业等级与交易清单、容器里的物品、拴绳、骑乘关系、掉落物与经验球。

还会丢的：生物骑生物只有基岩允许的那部分（马、猪、骆驼、驴的座位只认玩家，Java 里的「猪在马上」过去后骑手会站到旁边）；跨越区块边界的骑乘关系配不上，两个实体都在只是没骑上；数据包函数里的粒子不随存档走，只有命令方块与命令方块矿车里的会被改写。

具体每个版本补了什么，看 更新日志。

为什么两次转换，实体的顺序不一样？

实体记录的写入顺序每次都可能不同，这是引擎的并行调度决定的。游戏不依赖这个顺序，不影响游玩。

转换后进游戏方块变成空气 / 存档打不开？

先确认源存档开了哪些实验性玩法 —— 新方块在旧目标版本里不存在，会变成空气。其次用「存档详情」看一下版本声明对不对。

目标版本尽量选得比源版本新，或者至少同级。

怎么换语言？

「关于 → 语言」里可以在简体中文、English、日本語之间切换，默认跟随系统。

已知局限

写在这里是为了让你提前知道，而不是转完才发现。

  • 只支持标准 Java 版 / 基岩版存档，网易版存档不行。
  • 不支持分卷压缩包与加密压缩包。
  • 大存档受手机可用内存限制，转换期间需要留在前台。
  • 骑手与载具跨越区块边界时可能不配对；玩家自己拴的绳子挂不上。
  • 只存在于基岩版、所在列没有任何方块数据的实体，转回 Java 时会消失。
  • 存档详情只改头部字段，不做区块级修复。

这份清单随版本变化，最新的一份在 更新日志 里，源头是仓库的 VERSION.md。
